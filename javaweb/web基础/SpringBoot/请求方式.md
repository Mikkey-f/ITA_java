# 请求方式

在 Spring Boot 应用中，请求方式（HTTP Method）决定了客户端如何与服务器进行交互。常见的请求方式包括 **GET、POST、PUT、DELETE、PATCH** 等，每种方式都有特定的语义和使用场景。

### 一、常见请求方式及其应用场景

#### 1. **GET**

- **语义**：获取资源（不修改服务器状态）。
- **特性**：幂等（多次请求结果相同）、参数通过 URL 传递（不安全，有长度限制）。
- **示例**：查询用户信息、获取文章列表。

```java
@GetMapping("/users/{id}")
public User getUser(@PathVariable Long id) {
    return userService.getUserById(id);
}
```

#### 2. **POST**

- **语义**：创建新资源。
- **特性**：非幂等（多次请求可能创建多个资源）、参数通过请求体传递。
- **示例**：提交表单、上传文件。

```java
@PostMapping("/users")
public User createUser(@RequestBody User user) {
    return userService.saveUser(user);
}
```

#### 3. **PUT**

- **语义**：完整更新资源（覆盖原有数据）。
- **特性**：幂等（多次请求结果相同）、需提供完整数据。
- **示例**：修改用户的所有信息。

```java
@PutMapping("/users/{id}")
public User updateUser(@PathVariable Long id, @RequestBody User user) {
    return userService.updateUser(id, user);
}
```

#### 4. **DELETE**

- **语义**：删除资源。
- **特性**：幂等（多次请求结果相同）。
- **示例**：删除一篇文章。

```java
@DeleteMapping("/users/{id}")
public void deleteUser(@PathVariable Long id) {
    userService.deleteUser(id);
}
```

#### 5. **PATCH**

- **语义**：部分更新资源（仅修改指定字段）。
- **特性**：非幂等（多次请求可能导致不同结果）。
- **示例**：修改用户的邮箱。

```java
@PatchMapping("/users/{id}")
public User partialUpdateUser(@PathVariable Long id, @RequestBody Map<String, Object> updates) {
    return userService.partialUpdate(id, updates);
}
```

### 二、选择请求方式的原则

#### 1. **RESTful 规范**

- 使用 HTTP 方法表达操作意图，而非 URL 路径。
  - 错误示例：`POST /deleteUser?id=1`
  - 正确示例：`DELETE /users/1`

#### 2. **幂等性考虑**

- 若操作需保证幂等（如重试机制），优先使用 `GET`、`PUT`、`DELETE`。

#### 3. **参数安全性**

- 敏感数据（如密码）避免通过 `GET` 传递，应使用 `POST`、`PUT` 等。

#### 4. **数据量限制**

- `GET` 请求的参数受 URL 长度限制（通常约 2KB），大数据量使用 `POST`。

### 三、特殊场景处理

#### 1. **表单提交**

- **普通表单**：使用 `POST`（默认）或 `GET`（不推荐，参数会暴露在 URL 中）。
- **文件上传**：必须使用 `POST`，且 `enctype="multipart/form-data"`。

```java
@PostMapping("/upload")
public Result uploadFile(@RequestParam("file") MultipartFile file) {
    // 处理文件上传
}
```

#### 2. **复杂查询条件**

- 当查询参数较多时，可使用 `POST` + 请求体（需与前端约定）。

```java
@PostMapping("/search")
public List<User> searchUsers(@RequestBody SearchParams params) {
    return userService.search(params);
}
```

#### 3. **无明确语义的操作**

- 若操作不属于 CRUD（如触发任务），可使用 `POST` 或自定义 HTTP 方法（如 `@RequestMapping(method = RequestMethod.CUSTOM)`）。

### 四、Spring MVC 中的请求方式配置

#### 1. **快捷注解**

```java
@GetMapping    // 等价于 @RequestMapping(method = RequestMethod.GET)
@PostMapping   // 等价于 @RequestMapping(method = RequestMethod.POST)
@PutMapping    // 等价于 @RequestMapping(method = RequestMethod.PUT)
@DeleteMapping // 等价于 @RequestMapping(method = RequestMethod.DELETE)
@PatchMapping  // 等价于 @RequestMapping(method = RequestMethod.PATCH)
```

#### 2. **自定义请求方式**



```java
@RequestMapping(value = "/custom", method = {RequestMethod.GET, RequestMethod.POST})
public Result handleCustomRequest() {
    // 处理多种请求方式
}
```



### 五、请求方式与幂等性对照表

| 请求方式 | 语义               | 幂等性 | 安全性 | 参数位置            | 典型场景           |
| -------- | ------------------ | ------ | ------ | ------------------- | ------------------ |
| GET      | 获取资源           | ✅      | ❌      | URL 查询参数        | 查询列表、详情     |
| POST     | 创建资源           | ❌      | ✅      | 请求体              | 表单提交、创建记录 |
| PUT      | 完整更新资源       | ✅      | ✅      | 请求体              | 修改用户所有信息   |
| DELETE   | 删除资源           | ✅      | ✅      | URL 路径 / 查询参数 | 删除文章、用户     |
| PATCH    | 部分更新资源       | ❌      | ✅      | 请求体              | 修改用户部分信息   |
| HEAD     | 获取资源元信息     | ✅      | ❌      | 无                  | 检查资源是否存在   |
| OPTIONS  | 获取支持的请求方式 | ✅      | ✅      | 无                  | CORS 预检请求      |



合理选择请求方式不仅能提高 API 的规范性，还能避免因语义混淆导致的问题。在设计接口时，建议严格遵循 RESTful 原则，让请求方式与操作意图保持一致。
